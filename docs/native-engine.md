# Работа эфира (не интерфейс)

Интерфейс MirEfir свой. Этот файл — как должен работать **показ каналов**, чтобы нативный Windows/Android не упёрся в Chromium. Сценарии кнопок и меню: `docs/behavior-contract.md`.

Эталон работы (не внешнего вида): приставочные плееры на Android — один нативный декодер, картинка на отдельной плоскости экрана, оболочка сверху. Windows у них часто нет (эмулятор); у нас Windows — свой клиент на mpv.

## Как у них устроен эфир

1. **Плеер не в браузере.** Android: ExoPlayer/Media3 → аппаратный MediaCodec → SurfaceView (кадры идут на overlay, GPU оболочку не копирует каждый кадр). Windows-аналог: mpv с `vo=gpu/d3d11` в своём HWND. Не `<video>` + MSE, не WebView.
2. **Один живой экземпляр на сессию.** Стрелка вверх/вниз = подменить URL в том же декодере и той же поверхности. Не создавать окно, процесс, Surface, `<video>` заново.
3. **Картинка не ждёт гид, плейлист, оболочку.** Последний канал стартует сразу после M3U. XMLTV качается сбоку. Если гид молчит — эфир идёт.
4. **Живой поток чаще MPEG-TS по HTTP**, не только HLS. HLS — запасной (лишний манифест, выше задержка). UDP/RTP/RTMP встречаются в плейлисте — внутренний движок или внешний (VLC) должен это открыть, а не отдать Chromium.
5. **Старт короткий, подушка потом.** Порог до первого кадра маленький (порядка 0.3–2 с). Глубина буфера (`bufferSec`) — запас от рывков сети, не ожидание перед показом. Слишком большой старт = «заморозка» при каждом канале.
6. **Декодер: HW по умолчанию, SW если чёрный экран / только звук.** Переключение без переустановки приложения. HEVC на слабом ПК без HW — честный софт/отказ, не «мыло» через браузер.
7. **Обрыв сам лечится.** Таймаут соединения, повтор того же URL при stall/HTTP-ошибке. Пользователя не выкидывать в меню.
8. **Заголовки.** User-Agent и Referer из настроек/`#EXTVLCOPT`. Часть серверов режет неизвестный клиент.
9. **Дорожки.** Смена аудио (и субтитров, если есть) на лету, без нового `loadfile`.
10. **Xtream.** Не только `get.php?type=m3u_plus`. Живые URL умеют `.ts` и `.m3u8`; если TS не идёт — HLS. Архив — timeshift, как уже в `catchup.js`.
11. **Второй плеер «на соседний канал»** — необязателен. На слабом Pentium два HW-сеанса могут не влезть. Сначала быстрый replace на одном экземпляре.
12. **Лестница качества.** 4K/HEVC не открылся — тот же канал FHD → HD → SD и подпись на ~2 с, что устройство слабое. Не молчать.

Чего **не** копировать: безразмерный XMLTV в RAM, чужие экраны, чужие пункты меню.

## Как сейчас у MirEfir

| Место | Сейчас | Натив должен |
|---|---|---|
| Windows эфир | mpv child HWND, `loadfile replace`, idle+keep-open | Оставить этот принцип, убрать Electron вокруг |
| Android эфир | Capacitor WebView + hls.js | ExoPlayer + SurfaceView, без WebView для видео |
| Смена канала | mpv не убивается — хорошо; HTML-плеер каждый раз MSE | Только replace URL |
| Буфер | mpv `cache-secs=3` зашит; `bufferSec` крутит только hls.js | `decoder` и `bufferSec` реально крутят движок; старт короткий, подушка отдельно |
| Обрыв | `end-file error` — тишина, повтор нет | Watchdog ~8 с stall → тот же URL |
| Протоколы | HTTP(S) в mpv; MSE не любит сырой TS | HTTP-TS, HLS, плюс UDP/RTP если есть в M3U |
| Xtream | Собирается M3U `m3u_plus` | Плюс выход ts/hls, без обязательного гигантского M3U на каждый чих |
| EPG | gzip JSON, разбор в RAM (~сотни МБ) | Один файл на диске, окно из контракта, дописать+вычистить, запрос по каналу |
| UA | `MirEfir/1.0` | Настройка как сейчас, не ломать серверы |
| Оболочка над видео | Второе Chromium-окно OSD | Нативные виджеты поверх той же поверхности |

## Законы нативного клиента (чтобы не было «заморочек»)

1. Видео никогда не рендерить через Chromium/WebView/MSE.
2. Процесс плеера (mpv / ExoPlayer) живёт, пока жив эфир. Zap = `loadfile replace` / `setMediaItem`.
3. Эфир стартует, даже если EPG, логотипы и обновление плейлиста ещё идут.
4. Первый кадр не ждать полного `bufferSec`.
5. Настройки Плеер → декодер и буфер доходят до движка.
6. MPEG-TS live обязателен. HLS — запас.
7. Stall/ошибка потока → тихий reconnect того же канала.
8. Гид читает диск по `tvg-id`/имени, не держит весь XML в процессе.
9. Клиент живёт в `native/…`. Старый Chromium/Electron-код из репозитория убран (1.0.25).
10. Звук AC3/MPEG и сырой TS обязательны. 4K/HEVC — только если железо тянет, иначе FHD→HD→SD.
11. Запись по таймеру: отдельный dump живого URL, без второго декодера и без смены канала. Потом контейнер MP4 (копия, не перекодировка), запас MKV. Один таймер. Сценарий общий для Windows и Android.
